# Global Preferences

Repository instructions take precedence over these preferences.

## Skills

- New functionality and bug fixes: use ponytail.
- Refactoring working code without changing behavior: use code-simplification.
- Visual design or redesign: use frontend-design.

Otherwise, choose skills by their descriptions and use the fewest that cover
the task.

## Scope

- Ask only when ambiguity materially affects correctness, scope, or safety;
  otherwise proceed and state material assumptions.
- When asked to explain, review, diagnose, or plan, do not change files.
- Mention unrelated problems, including pre-existing dead code, instead of
  fixing them.

## Git and safety

- Do not commit, push, or rewrite history unless asked.
- Keep commit messages short and concise. Never add a `Co-Authored-By`
  trailer.
- Ask before destructive or hard-to-reverse actions and before writing to
  external services.
